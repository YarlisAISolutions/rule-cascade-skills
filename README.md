# Rule Cascade skills and plugin for AI coding agents

Skills, sub-agents and the MCP server that let an AI coding agent find the business rules in your
code, write them as [Rule Cascade](https://rulescascade.com) rulesets with golden tests, review
them, and enforce them in TypeScript, Python, Java, Go or any other language.

> Generated by `rcas agent install` (Rule Cascade 1.0.0-alpha.10) on each release.
> Changes made directly in this repository are overwritten by the next release.

## Claude Code plugin

The skills, the four sub-agents (`rcas-analyst`, `rcas-author`, `rcas-reviewer`, `rcas-tester`),
the commands and the MCP server, in one install:

```text
/plugin marketplace add https://rulescascade.com/skills.git
```

```text
/plugin install rules-cascade@rules-cascade
```

Commands: `/rules-cascade:rcas-capture`, `/rules-cascade:rcas-review`.

To offer it to everyone who opens a repository, commit this to `.claude/settings.json`:

```json
{
  "extraKnownMarketplaces": {
    "rules-cascade": { "source": { "source": "git", "url": "https://rulescascade.com/skills.git" } }
  },
  "enabledPlugins": { "rules-cascade@rules-cascade": true }
}
```

## Any agent: skills with npx

Codex, Cursor, GitHub Copilot, Gemini CLI, OpenCode, Amp, Goose, Claude Code and others that read
[Agent Skills](https://agentskills.io):

```bash
npx skills add https://rulescascade.com/skills.git
```

| Skill | What it does |
| --- | --- |
| `rules-cascade` | Find business rules in code and turn them into Rule Cascade rulesets (YAML, golden tests, rcas check). Use when the user asks to extract, write, review, test or change business rules, validations, limits or approvals, or mentions rcas, rulesets or Rule Cascade. |
| `rules-cascade-architecture` | Explain how Rule Cascade is designed and how a project uses it (rulesets, bundles, engines, enforcement, inheritance, rcas). Use when the user asks how Rule Cascade works, why it is built a certain way, which engine form to use (library, command, WebAssembly, rule server), how rules reach a browser or a service, or how to set it up in a project. |
| `rules-cascade-capture` | Find the business rules in a folder, module or feature and propose rulesets for them. Use when the user asks to find, extract or capture the business rules of a folder, a module, a feature or the whole project. |
| `rules-cascade-engine` | Enforce Rule Cascade rules from any language without a native library - C#/.NET, Rust, PHP, Ruby, Swift, Kotlin Native, C++, shell - through the rcas engine process (JSON Lines) or the rcas.wasm WebAssembly module. Use when the project's language has no Rule Cascade package, or rules must run in a sandbox or a database job. |
| `rules-cascade-go` | Enforce Rule Cascade rules in Go services and tools (net/http, chi, gin, echo, gRPC, workers) with rulescascade.com/go. Use when wiring rules into a Go code path, replacing validate tags or hand-written checks with the engine, or mapping rule findings to HTTP or gRPC errors. |
| `rules-cascade-java` | Enforce Rule Cascade rules on the JVM - Java 17+, Kotlin and Scala; Spring Boot, Quarkus, Micronaut, Jakarta EE - with com.rulescascade:rules-cascade-core. Use when wiring rules into a JVM service, replacing Bean Validation or hand-written checks with the engine, or mapping rule findings to HTTP errors. |
| `rules-cascade-migrate` | Move business rules out of application code into Rule Cascade step by step - inventory the checks, propose rulesets, prove parity, switch the code to the engine, delete the old checks. Use when the user wants to adopt Rule Cascade in an existing code base, centralise validations scattered across services and front ends, or replace a specific check with a rule. |
| `rules-cascade-python` | Enforce Rule Cascade rules in Python services and jobs (FastAPI, Django, Flask, Celery, batch scripts) with the rule-cascade package. Use when wiring rules into a Python code path, replacing Pydantic validators or hand-written checks with the engine, or evaluating many records in a batch. |
| `rules-cascade-review` | Review a Rule Cascade ruleset change or proposal before it is accepted - ids and codes, version bump, enforcement channel, overrides, risk acceptance, golden tests, messages, portable patterns. Use when the user asks to review rules, a ruleset diff, a pull request touching *.ruleset.yaml, or a proposal from rcas proposals. |
| `rules-cascade-typescript` | Enforce Rule Cascade rules in TypeScript and JavaScript - Node.js services (Express, Fastify, NestJS, Next.js route handlers, node:http) with @rules-cascade/core, and browsers or React Native forms with the client manifest and @rules-cascade/client. Use when wiring rules into a Node or browser code path, replacing Zod/Joi/class-validator checks with the engine, or showing rule findings in a form. |

The skills assume the default layout: rulesets in `rules/`, bundles in `build/rules/`.

## Everything, in the format of each tool

`rcas agent install` writes the same skills for about twenty AI coding tools, each in the format it
documents (scoped instructions, commands, sub-agents limited to the tools their role needs), and
follows your `rcas.yaml`. `rcas mcp install` registers the MCP server:

```bash
npx -y @rules-cascade/cli agent install
npx -y @rules-cascade/cli mcp install
```

See [AI coding tools](https://rulescascade.com/agents/).

## MCP server only

```bash
claude mcp add rules-cascade -- npx -y @rules-cascade/cli mcp
```

Or the hosted server, which needs no installation but cannot propose rulesets:
`https://mcp.rulescascade.com/mcp`.
